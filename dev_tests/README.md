# dev_tests — BadaPromptGenerator verification harness

Throw-away verification scripts for the `BadaPromptGenerator` node. They talk to a
**live** ComfyUI instance over HTTP (they never import ComfyUI internals), so they
must be pointed at a scratch instance instead of the daily driver on port `8188`:

```powershell
$env:BADA_TEST_BASE = "http://127.0.0.1:8199"   # scratch instance (default anyway)
```

| script | what it proves |
| --- | --- |
| `bada_promptgen_exec_test.py` | Backend **execution** path. Queues `enhance=false` (no Gemini call), then asserts the node executed, `generated_text` passed `request_text` through verbatim, `wh_ratio` stayed empty, the `bada_promptgen_toast` ui key was emitted, and a downstream consumer node actually received the text. |
| `bada_promptgen_ui_smoke.py` | Frontend **browser** path (Playwright/Chromium, headless). 49 checks: boot/registration, node header DOM, toggle-card ↔ BOOLEAN widget sync (both directions), cascading `target → submenu`, toast rendering from a websocket `executed` payload, API-key row (mask/reveal/empty-key warning), model select → localStorage + `config.json`, modal CRUD (create/load/reorder/delete), and modal → registry → node `submenu` integration (no restart). |
| `bada_promptgen_live_check.py` | **Read-only** readiness probe for an already-running instance (defaults to port `8188`). Confirms the registry route answers, `BadaPromptGenerator` is in `/object_info`, and the browser-side assets (`bada_prompt_generator.js` / `.css`, `bada_promptgen_modal.js`, `bada_i18n.js`) are served with the latest markers. Mutates nothing — safe on the daily driver. |
| `bada_saveas_ui_smoke.py` | Frontend **browser** path for the Save As Folder Picker. 24 checks: extension boot, `ComfyWorkflow.prototype.promptSave` hook, `Comfy.SaveWorkflowAs` opening the Bada dialog, the Windows Explorer-style tree (root row first, first-level folders matching the tree API, a parent expanding with a `▼` chevron and its child appearing at a deeper indent), in-place folder creation + auto-select + breadcrumb, live target-path preview, the real save landing on disk at `<root>/<folder>/<name>.json`, and the Cancel path. Creates a blank temporary workflow first (never renames a real file) and deletes every artifact afterwards, so it is safe on the daily driver. |
| `bada_folder_rename_test.py` | Workflow+ sidebar **folder** rename/move. 53 checks against the real `server/bada_server_api.py` handlers: the reported 404 regression, no `.json` suffix on folders, nested renames, folder moves, guard rails (self-subtree 400, duplicate target 409, illegal/reserved Windows names 400, path traversal 400, root protection 403), case-only renames, `.bada_meta.json` note/thumbnail migration, the unchanged workflow-file path, and the **model-scan TTL cache / `asyncio.to_thread` offload** (cold → warm → TTL expiry → an empty scan is never cached, plus the handlers must not call the blocking walk inline). **Hermetic** — stubs `server.PromptServer`, `folder_paths` **and `aiohttp`** and works on a temp directory, so it needs no running instance, no `pip install`, and never touches your real workflows folder. |
| `bada_async_gemini_layout_test.js` | BadaAsyncGeminiStudio **panel slimming + chat bubble layout** (Node, no browser needed). **Chat history popup (📌 list ceiling + pin, 15 checks):** the list carries its **own `max-height`** (~15 rows) rather than inheriting the panel's cap — without it the list only stopped growing at the *panel* ceiling, so from the 12th conversation on the popup filled most of the screen and pushed the footer (이미지 설정 · 백업 · 전체 삭제) to the very bottom edge. **15 rows, not 10**, because the pinned block sits at the **top** of that same list: with only 10 rows visible, every extra pin pushes the unpinned conversations off screen, so the thing forced to scroll would be the wrong list. The **panel** ceiling is asserted to be at least `list + 250px` — raising the list alone is a no-op, since a 690px list inside a 760px panel leaves ~70px for the head, search box and footer and gets cut straight back down. `overscroll-behavior: contain` keeps scrolling from chaining past the overlay, while `min-height` stays so a 1–2 chat store still gets a usable box. **🖼️ 썸네일 (8 checks):** up to three **28px** previews per conversation, read back from the real DOM — `getBoundingClientRect()` proves they are actually 28×28 on screen, `complete`/`naturalWidth` prove they **decoded** (a strip of blank `<img>`s looks correct in the DOM and wrong on screen), and the `src` prefix proves they are the downscaled JPEGs rather than the originals. Rows without images are asserted to carry **no strip at all** — an element per row would add 30 empty cells — and the strip must be clickable. Everything is SKIPped, never silently passed, when the install holds no image-bearing conversation. **🕐 토글 · 배경막 누출 (6 checks):** the 🕐 button used to only ever **OPEN** — dismissal was reachable from Esc, a canvas click and the backdrop, but never from the button itself. Re-clicking it therefore mounted a **second** popup and orphaned the first one's full-viewport `rgba(0,0,0,.45)` backdrop: a dim over the whole canvas that nothing could dismiss, reported as 「창을 닫으면 검정색으로 화면을 가리고 있어」. Compounding it, `chatHistoryHandle` was assigned only **after** the `await`s, so the `if (handle)` guard was false for the whole opening window. The button now toggles, the handle is released **before** the awaits, a failed open releases it too (a latch would kill the button permanently), and every dismissal reports back through `onClose` so Esc/canvas closures clear the owner's handle. Asserted on the count of **painted** backdrops — a dozen full-viewport backdrops from other extensions sit in `document.body` permanently at `display:none`, and counting those would point at the wrong component. pinning **re-reads the list** instead of patching the local row (pinning moves the row, and that ordering is the server's to decide); the search filter runs **before** the pinned/unpinned split, so a query matching no pinned chat renders no empty 「고정됨」 band. The server side is asserted from the same file because the UI's promise ("this one is never auto-deleted") has three independent ways to break: `_prune` must count the cap over **unpinned rows only**, `upsert_chat` must copy `pinned` forward (it **replaces** the stored dict, so an uncopied flag dies on the next message in that chat), and `import_store` must restore it (otherwise the pin is lost on the one action meant to preserve the user's work). **Chat bubbles run full width on BOTH sides**, told apart by a filled background (user) vs no background + thin border (model) — the old `justify-content: flex-end/flex-start` pair left a wide gutter beside every message and capped the bubble at 86%. The subtle part is pinned explicitly: `max-width: 100%` **alone does not work**, because the bubble is a flex item and defaults to `flex: 0 1 auto`, shrinking to its content width (a short user message still left a 252 px gutter in a 427 px thread) — only `flex: 1 1 auto` actually fills the row, and `min-width: 0` keeps a long token from forcing a horizontal scrollbar. Removing the `flex-start`/`flex-end` rules is asserted as GONE, not merely unused, since re-adding one is the exact regression. Also 53 checks pinning six removals that shrink the panel by six rows: the **green completion banner**, the **blue "working" banner** and the **제미나이 chat completion banner** (all `.bada-toast` block children that shoved the panel down), the `Pass N` status badge, the in-panel `⚓ Bada Async Gemini Studio` title that duplicated the node title, and the header row itself (which, once the title went, was an empty full-width box holding only the ZERO-REFUSAL / NON-BLOCKING badges). Also pins the 🔔 bell relocation into the API-key label row — it is no longer a descendant of `header`, so a leftover `header.querySelector` would resolve to `null` and silently kill the error-notification log while every other test still passed. Scoped deliberately: short **action** toasts (copy / API-key check) are kept, because those are confirmations rather than layout-shifting banners, and a generation-worded scan guards against any banner coming back. Finally asserts what must **survive**: `showToast` (errors still surface), the chat error toast, the reply bubble's inline `⏱️ N.N초 완료` timer, the generate button's spinner/timer/Stop, the NSFW and Korean-translation chips (`.bada-toggle-badge`, a *different* class from the removed `.bada-badge`), and the shared `.bada-subtext` class (still used by the character and image counters). Also pins the **2026-10-05 paste fixes**: the image-attach success banners are gone (they were the last layout-shifting toast — the thumbnail strip is the confirmation now) while the *error* toasts stay, the paste handler routes by tab (`handleChatImageFiles` on 제미나이 vs `handleFiles` elsewhere, the former filling `chatUploadedImages`, never the shared strip), and the listener is registered on `document` in the **CAPTURE** phase with `stopImmediatePropagation()` rather than bubbled from `window`. Absence assertions run against `stripComments(JS)`, since the prose around them names the removed symbols on purpose. Also pins the **2026-10-05 chat-history scope fix and 제미나이 drag & drop**: `renderChatImagesPreview` / `renderChatMessages` / `renderChatLengthNotice` are declared *inside* `renderChatStudio()` while `restoreChat()` and the popup's `onRestore` live outside it — calling them by name threw `X is not defined` and killed 「이어하기」 on the first press, so the check requires those paths to go through the published `refresh*` bindings and requires each binding to actually be assigned (an unpublished one is a silent no-op). The body is sliced by **brace matching** and comment-stripped first, since a sentinel-indent search overran the function and an explanatory comment merely *naming* the inner symbol is not a call site. The drop path pins both `preventDefault` **and** `stopPropagation` (ComfyUI listens on the canvas, so without the latter one gesture would create a node as well as an attachment), the `Files`-type filter that stops text drags lighting the panel, the drag-depth counter that prevents flicker when the pointer crosses child elements, teardown on tab switch (otherwise listeners stack and one drop attaches the image N times), the overlay's `pointer-events: none` (without it the overlay swallows the drop), and that deleting a thumbnail removes the same index from `chatOriginalImages` so 「원본으로 저장」 cannot re-attach the wrong image. |
| `bada_gemini_chat_history_test.py` | 제미나이 **채팅 기록 저장소** (Python, hermetic — stubs `aiohttp`, no running instance, no `pip install`). **80 checks** driving the nine REST routes in `server/gemini_chat_history.py` against a **temp directory**: all routes registered; a save mints an id and derives the title from the first user message; **upsert updates in place** instead of appending a duplicate row; the list payload carries counts but **never message bodies or image bytes**; the **30-conversation cap** holds under a flood and drops the *oldest*; `clear` refuses without `confirm` and leaves the data intact; `export` → `import` round-trips every chat, **merges** rather than replaces, and re-importing your own backup adds nothing. Pins the image policy: 「저장 안 함」 stores **no bytes** yet keeps the **count** and the `imagesOmitted` flag, so a restored thread still renders `🖼️ 이미지` placeholders. **📌 상단 고정 (pin):** the store is pushed to 30, the **oldest** row is pinned, then 10 more saves arrive — the pinned chat must still be there and the **31st** row proves the cap now counts **unpinned only**. Unpinning hands the row *back* to the cap (it is evicted by the very next save, which is the only way to prove the exemption was real rather than a larger cap). Two silent-loss paths are pinned because both are invisible when they happen: `upsert_chat` **replaces** the stored dict wholesale, so the flag has to be copied forward or the pin dies the moment the user sends again in that conversation; and `import_store` dropped `pinned` entirely, so the user's protection was lost on **백업 → 복원** — the one action meant to preserve their work. Pinning is deliberately **not** treated as activity (`updatedAt` is untouched), so unpinning does not make an ancient chat jump the queue. `pinned: "false"` is asserted to **unpin**: `bool("false")` is `True` in Python, so a stringified checkbox would pin the very chat the user just unpinned, with no error to show for it. **🖼️ 썸네일 (thumbs):** a 1200×800 PNG comes back as a **28px JPEG of ~415 B — under 7% of the source**, and the assertion decodes it again in Pillow to prove the *pixels* are downscaled, not merely that the byte count looks small. Order is **newest-first** (`n=1` must equal the first entry of `n=3`), `n` caps the count, 「저장 안 함」 yields **no preview but still reports `omitted`**, and corrupt/oversized inputs must degrade to `[]` rather than a 500 — a preview is decoration. `n`/`size` are **clamped** (1–6, 16–128px) because they are attacker-controllable and this route decodes base64 server-side. The route reads `request.rel_url.query`, not `request.query`: the latter raised `AttributeError` and 500'd a perfectly valid request. The LIST payload is re-asserted to carry **no base64 and no bodies**, which is the entire reason previews live on their own endpoint. **Recency regressions:** `updatedAt` is second-precision, so a burst of saves shared one timestamp and Python's stable sort made the 30-cap prune by *insertion* order, silently discarding the conversation just written — `updatedAtMs` is the authoritative key, synthesized for backups written before it existed. **Empty-input regressions:** a whitespace-only message (`"  "` is truthy in Python) used to persist an empty-looking bubble and inflate the KB counter, and an empty thread is a 400. The sort-key assertion reads the **list** endpoint over the populated store — it previously iterated a leftover empty list, where `all([])` returned `True` and the check passed without asserting anything. |

> Is your main instance already up to date? `python dev_tests/bada_promptgen_live_check.py`
> — if it prints `READY`, you only need a browser hard refresh (<kbd>Ctrl</kbd>+<kbd>F5</kbd>);
> a server restart is only required after editing Python files.

Requirements (install into the ComfyUI venv or any Python 3.10+):

```powershell
pip install requests playwright
playwright install chromium
```

> `bada_saveas_ui_smoke.py` also works when only the regular `chromium-*` build is
> cached (no `chromium_headless_shell-*`): it detects the missing headless shell and
> relaunches with `channel="chromium"` automatically.
> If `import requests` suddenly fails with a `python39.dll` conflict, clear the
> `PYTHONPATH` environment variable for the test run.

Run:

```powershell
python dev_tests/bada_promptgen_exec_test.py
python dev_tests/bada_promptgen_ui_smoke.py      # screenshots -> dev_tests/_shots (gitignored)
python dev_tests/bada_saveas_ui_smoke.py         # Save As folder picker (safe on 8188)
python dev_tests/bada_folder_rename_test.py      # folder rename/move (no instance needed)
node   dev_tests/bada_folder_drag_test.js       # folder drag & drop (no instance needed)
```

> `bada_folder_rename_test.py` and `bada_folder_drag_test.js` are the odd ones out: neither
> talks to a live instance. The Python one imports the real REST handlers with
> `server.PromptServer` / `folder_paths` stubbed and drives them against a temp directory; the
> Node one loads the real sidebar class with `vm` and stubs the browser globals. Both are
> therefore safe to run anywhere and never touch your real workflows folder. The Python script
> needs `aiohttp` (use the ComfyUI interpreter); the Node script needs only `node`.

Both scripts exit non-zero on the first failed check and print a `PASS/FAIL` line
per assertion. The UI smoke test is **idempotent**: every prompt it creates is
deleted again and `config.json`'s `default_model` is restored, so it can be
re-run at any time. Scratch artifacts:

- `dev_tests/_shots/*.png` — per-section screenshots (`BADA_TEST_SHOTS` overrides the path)
- `engines_registry.json.bak` — snapshot written by the REST API before each save (gitignored)

> Note: ComfyUI history only stores outputs of `OUTPUT_NODE`s, which is why the
> exec test verifies the data flow through a downstream consumer node
> (`ShowText` / `PreviewAny`) rather than reading node 1's own outputs.
